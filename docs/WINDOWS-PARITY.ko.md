# Windows 기능 동등성

[English](WINDOWS-PARITY.md) · [Windows 빌드](../windows/README.ko.md)

macOS 앱에 실제로 구현된 기능을 기준으로 Windows 이식 상태를 정리했습니다.
Markdown 명세 전체의 지원 여부를 뜻하지 않습니다. `dab90e4` 이후 현재의 읽기·세션
변경을 포함합니다. **구현됨; 실제 조작 검증 필요**는 코드가 있지만 전체 사용 흐름의
수동 검증은 남아 있다는 뜻입니다. Windows에서 확인한 범위는 아래에 따로 적었습니다.
Windows 앱은 아직 개발 빌드입니다.

## 문서 읽기와 목록

| 기능 | Windows 상태 | 완료 조건 |
| --- | --- | --- |
| 로컬 파일 | 구현됨; 실제 조작 검증 필요 | 파일 선택, 실행 인수, 탐색기·바탕화면 드롭으로 여러 UTF-8 문서를 엽니다. 한글·공백 경로를 지원하고 폴더, 잘못된 UTF-8, 16 MiB 초과 파일을 거부합니다. 중복 파일은 기존 항목을 선택합니다. |
| 사이드바와 목차 | 구현됨; 동등성 검증 필요 | 사이드바 접기, 목차 표시 전환, 중첩 제목 이동이 문서 순서나 선택을 바꾸지 않아야 합니다. 다른 문서 구간의 제목으로도 이동해야 합니다. |
| 문서 제거 | 구현됨; 실제 조작 검증 필요 | 개별 제거와 확인 후 전체 제거를 지원합니다. 취소하면 목록을 유지하고 원본 파일은 삭제하지 않습니다. |
| 정렬 | 일부 구현 | 추가 순서, 이름, 최근 수정 순서를 지원하고 동률 순서와 선택을 유지합니다. 기준 빌드는 이름 오름차순·내림차순만 제공합니다. |
| 블록 서식 | 일부 구현 | 공통 예제로 제목, 문단, 중첩 목록, 인용, 구분선, 코드 블록을 비교합니다. 번호 목록의 시작 번호를 유지해야 합니다. |
| 인라인 서식과 표 | 구현됨; 실제 조작 검증 필요 | 강조, 굵게, 취소선, 인라인 코드, 이스케이프, 링크, 표 정렬을 macOS 예제와 비교합니다. 링크는 문서 출처에 맞는 탐색 정책을 따라야 합니다. |
| 찾기·글자 크기·복사 | 구현됨; 실제 조작 검증 필요 | 현재 찾기는 개별 출현 위치가 아닌 일치하는 블록을 이동하며 강조 표시는 없습니다. 큰 표는 별도 페이지 이동이 필요합니다. 글자 크기 조절과 전체 일반 텍스트 복사는 구현했지만 선택은 블록 단위입니다. 연속 선택과 출현 위치별 찾기는 남아 있습니다. |
| 새로 고침·복사본 저장 | 구현됨; 실제 조작 검증 필요 | 변경된 파일을 직접 새로 고칠 수 있어야 합니다. 복사본은 렌더링 결과가 아닌 BOM을 포함한 원본 바이트를 보존합니다. 파일 선택을 취소하면 아무것도 바꾸지 않습니다. |
| 테마·세션 복구 | 구현됨; 실제 조작 검증 필요 | 재시작 후 선택 문서, 목록, 테마, 목차·사이드바 설정을 복원합니다. 파일 누락이나 상태 파일 손상 시 복구 가능한 데이터를 조용히 버리지 않습니다. 문서별 구간·스크롤 복원도 구현했으나 Windows 검증이 필요합니다. |
| 파일 위치·전체 화면 | 구현됨; 실제 조작 검증 필요 | 탐색기에서 로컬 원본 위치를 표시합니다. F11로 전체 화면을 전환하고 컨트롤 접근과 종료 수단을 제공합니다. 현재 앱 내부 컨트롤은 계속 표시합니다. macOS처럼 마우스를 올리면 상단을 표시하는 동작은 남아 있습니다. |

macOS 렌더러도 문서에 삽입된 이미지의 픽셀을 내려받아 표시하지는 않습니다.
따라서 이미지 렌더링은 동등성의 필수 조건이 아닙니다. 읽을 수 있는 대체 텍스트를
유지하고 자동 네트워크 요청을 추가하지 않습니다. 두 앱 모두 Markdown 편집기가
아닙니다. Windows의 문서 구간 분할 표시도 연속적인 화면 영역 가상화와 다르므로,
화면이 비슷하다는 이유만으로 성능까지 같다고 판단하지 않습니다.

## 입력·내보내기·배포

| 기능 | Windows 상태 | 완료 조건 |
| --- | --- | --- |
| 클립보드 Markdown | 구현됨; 실제 조작 검증 필요 | 유효한 텍스트를 앱 저장소에 보관하고 재시작 후 복원합니다. 목록 제거와 영구 삭제를 구분하며 입력은 16 MiB로 제한합니다. |
| 가져온 문서 관리 | 미구현 | 보관된 문서 조회, 복사본 저장, 명시적인 영구 삭제를 지원합니다. 목록에서 제거해도 내용은 남깁니다. 현재 클립보드 경로는 목록에서 제거한 문서를 보존하고 256 MiB로 제한하지만 관리 화면은 없습니다. 쓰기 중단 후 복구도 검증해야 합니다. |
| HTTPS Markdown | 미구현 | 원본 HTTPS 주소와 GitHub 파일 주소를 지원합니다. 인증 정보·지원하지 않는 콘텐츠를 거부하고 다운로드 크기, 리디렉션, 시간을 제한합니다. 취소, 오프라인 캐시 열기, 안전한 상대 링크 해석을 지원합니다. |
| LLM·CLI 전달 | 일부 구현; Windows 검증 필요 | 파일 인수와 기존 앱으로의 전달을 구현했습니다. 기존 앱에는 절대 경로가 필요하며 상대 경로는 거부합니다. HTTPS, UTF-8 표준 입력, 제목 지정은 남아 있습니다. 비공개 수신함의 크기·내용을 검증하고 대기 요청 복구와 중복 방지를 지원합니다. 종료 코드와 PowerShell 사용법을 문서화합니다. MCP 서버는 필수가 아닙니다. |
| PDF 내보내기 | 미구현 | 선택한 문서의 스냅샷을 페이지, 표, 링크, 유니코드가 읽히는 PDF로 내보내고 결과를 눈으로 확인합니다. 취소, 문서 전환, 저장 오류로 내용이 섞이거나 손상되지 않아야 합니다. |
| 파일 연결 | 미구현 | 설치 시 `.md`, `.markdown`, `.mdown`을 탐색기 **연결 프로그램**에 등록합니다. 사용자가 기본 앱으로 선택하면 더블클릭으로 엽니다. 제거 시 SSMV 등록만 지웁니다. |
| 업데이트 안내 | 미구현 | Windows 배포 채널부터 결정합니다. 알림 없이 앱을 교체하거나 Windows 사용자에게 Homebrew를 안내하지 않습니다. macOS는 기존 tap과 Homebrew 업데이트 안내를 유지합니다. |
| 도움말·About | 미구현 | 제품명, 버전, Windows 단축키를 제공합니다. 문서는 영문을 기본으로 하고 한국어는 별도 링크합니다. |

Windows에서는 macOS의 Command 단축키에 대응하는 Ctrl+O, Ctrl+F, Ctrl+C,
Ctrl+A를 사용하고 전체 화면은 F11을 기준으로 합니다. macOS 전용 Fn·지구본
표기를 Windows 메뉴에 옮기지 않습니다.

## 검증 조건

- [ ] 공통 예제로 Markdown, 목차 순서, 유니코드, 잘못된 입력을 비교합니다.
- [x] Windows x64·ARM64 빌드를 통과하고 실제 실행을 검증한 아키텍처를 명시합니다.
- [ ] Windows에서 탐색기 드롭, 파일 선택, 포커스, 키보드, 배율, 내레이터, 테마, 재시작 복구를 확인합니다.
- [ ] 15 MiB 문서를 포함한 동일 자료로 실행 시간, 첫 표시 시간, 메모리, CPU, 반응성을 측정합니다. 크기 제한은 속도 보장이 아닙니다.
- [ ] 공개 배포 전에 외부 링크 처리, 비공개 저장소, 네트워크 제한, 외부 코드 라이선스를 확인합니다.
- [ ] 공통 빌드나 저장소 구조를 변경하면 macOS 회귀 테스트를 다시 실행합니다.

문서·Markdown·세션 테스트 3개 모음과 x64·ARM64 빌드를 통과했습니다.
[x64 자동 실행 검증](https://github.com/raeseoklee/ssmv/actions/runs/35182699940)에서는
최초 실행과 기존 창으로 파일 전달, 구간 검색 결과 있음·없음, 글자 크기·다크 테마 변경,
두 문서의 순서·선택 복원, 읽기 설정 저장, 정상 종료를 확인했습니다. 공개 예제 화면에서
서식과 3열 표의 줄바꿈도 확인했습니다. 모든 조작이나 ARM64 실행까지 검증한 것은 아닙니다.

현재 읽기·세션 작업의 검증 다음에는 가져온 문서 관리와 URL·CLI 전달을 우선하고,
PDF와 설치 연동을 진행합니다. 검증을 통과한 기능만 지원한다고 안내하며,
문서 수정만으로 앱 버전을 올리지 않습니다.
